# azureml-mlflow registers MLflow's "azureml://" tracking-store scheme —
# without it, mlflow.set_tracking_uri() on an Azure ML workspace URI fails
# with UnsupportedModelRegistryStoreURIException, even though nothing in
# this project imports azureml_mlflow directly (it's discovered via a
# setuptools entry point, invisible to `pip show`'s reverse-dependency
# check — don't mistake it for an unused package).
#
# It's deliberately NOT listed as a normal line above: its own declared
# pins (azure-storage-blob<=12.27.1, mlflow-skinny<=3.13.0) are older than
# what mlflow==3.14.0 and mltable's azureml-dataprep actually need, and
# those two ranges have NO overlapping version at all — pip's resolver
# refuses to install this file in one pass if azureml-mlflow is a normal
# line here (ResolutionImpossible). Install it separately, with --no-deps,
# AFTER everything above:
#
#   pip install -r requirements.txt
#   pip install --no-deps azureml-mlflow==1.62.0.post5
#   pip install azure-common jsonpickle
#
# The third line installs two of azureml-mlflow's own direct imports that
# --no-deps skipped (they're not version-conflicted, just skipped along
# with everything else --no-deps omits) — not optional, azureml-mlflow
# fails to import without them.
#
# This is a tested, working exception, not a guess: this project never
# calls the Data Lake-specific APIs where the azure-storage-blob mismatch
# would matter, and full Azure ML MLflow tracking (used throughout
# azure_automl.py) works correctly with the newer versions installed
# above despite azureml-mlflow's own metadata claiming otherwise.
